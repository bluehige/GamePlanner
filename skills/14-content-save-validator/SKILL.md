# Content and Save Validator

게임 데이터와 저장 파일을 코드의 부속물이 아니라 **장기 호환 계약**으로 취급한다. ID, 참조, 스키마, 마이그레이션, 라운드트립을 자동 검사한다.

## 사용 시점

- 몬스터, 아이템, 스테이지, 퀘스트, 대사, 스폰 테이블을 추가·삭제·이름 변경할 때
- 저장 구조나 버전을 변경할 때
- 대규모 CSV·JSON·Resource·DataTable을 수정할 때
- 플랫폼 이식, 현지화, DLC·업데이트를 준비할 때

## 입력

- 콘텐츠 스키마와 source-of-truth 데이터
- 현재 및 지원 대상 이전 저장 샘플
- ID·경로·리소스 명명 규칙
- 마이그레이션 함수와 버전 정책
- 엔진 임포트 결과와 패키징 대상 목록
- 관련 Work Order와 Change Impact 보고서

## 절차

1. 콘텐츠 타입별 필수 필드, 타입, 범위를 검사한다.
2. 전역·타입별 ID 중복을 검사한다.
3. 모든 참조가 존재하고 허용된 타입을 가리키는지 검사한다.
4. 삭제·이름 변경된 ID의 마이그레이션 또는 별칭을 확인한다.
5. 스폰·드롭·진행 그래프의 도달 불가와 순환 의존성을 찾는다.
6. 자산 파일, 임포트 리소스, 현지화 키 누락을 찾는다.
7. 파일명 대소문자와 플랫폼 경로 규칙을 검사한다.
8. 이전 저장을 최신 버전으로 마이그레이션한다.
9. 로드 → 저장 → 재로드 라운드트립에서 의미 보존을 검사한다.
10. 결정적 시드와 반복 실행 결과가 필요한 시스템을 비교한다.
11. 손상·중단·부분 저장 시 복구 정책을 검증한다.

## 필수 검사

- 중복 ID와 빈 ID
- 존재하지 않는 리소스 참조
- 허용되지 않는 역참조와 순환
- 범위를 벗어난 수치·확률 합계
- 누락된 현지화 키와 자리표시자 불일치
- 패키지에서 제외된 파일
- 이전 저장 버전별 마이그레이션 경로
- 마이그레이션의 멱등성
- 라운드트립 데이터 손실
- 대소문자 민감 플랫폼 실패
- 랜덤 시드 재현성

## 하드 게이트

- 공개된 ID를 단순 이름 변경으로 삭제하지 않는다.
- 저장 버전 증가 없이 구조를 바꾸지 않는다.
- 마이그레이션 실패 시 조용히 새 게임으로 초기화하지 않는다.
- 에디터에서 보인다는 이유로 패키지 포함을 가정하지 않는다.
- 원본 저장 샘플을 덮어쓰지 않는다.
- 데이터 자동 수정은 변경 내역과 롤백 파일을 남긴다.

## 완료 게이트

- 모든 콘텐츠 ID와 참조가 검사됐다.
- 지원한다고 선언한 이전 저장이 실제로 마이그레이션됐다.
- 라운드트립과 실패 복구를 검증했다.
- 플랫폼별 경로·패키징 차이를 확인했다.
- 치명적 오류 0건이며 허용된 경고는 근거가 있다.
