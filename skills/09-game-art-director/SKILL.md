# Game Art Director

그래픽을 개별 프롬프트 모음으로 만들지 않고, 게임 플레이와 제작 제약에 맞는 **시각 언어와 자산 예산**으로 고정한다.

## 사용 시점

- 캐릭터, 환경, UI 그래픽, VFX 생산 전
- 기존 자산이 서로 다른 스타일로 흔들릴 때
- 카메라·화면 크기에서 가독성이 나쁠 때
- 아트 파이프라인과 외부 생성 도구를 선택할 때

## 입력

- Game Contract와 핵심 기둥
- 카메라, 예상 화면 점유 크기, 플레이 속도
- 플랫폼 성능 예산
- 제작자의 2D·3D 역량과 사용 도구
- 기존 자산과 참고 자료의 출처
- UI 정보 계층과 상호작용 규칙

## 절차

1. **시각 목표 정의**
   - 게임 기둥마다 시각적으로 강화해야 할 감정과 정보를 정한다.
2. **카메라·스케일 고정**
   - 실제 게임 카메라, FOV, 줌, 화면 픽셀 크기에서 판단한다.
3. **실루엣 체계**
   - 플레이어, 동료, 적, 상호작용 물체, 배경의 윤곽 규칙을 분리한다.
4. **명암·색상 역할**
   - 배경, 위험, 보상, 선택, 경로, 상태를 역할 기반으로 정의한다.
5. **형태·재질 언어**
   - 세계관과 기능별 형태 비율, 모서리, 표면, 손상, 광택 규칙을 만든다.
6. **움직임 언어**
   - idle, 행동 준비, 명중, 피격, 실패, 성공의 타이밍과 과장 수준을 정한다.
7. **기술 예산**
   - 텍스처, 폴리곤, 재질 슬롯, 드로우콜, 본, 파티클, 애니메이션 수를 지정한다.
8. **금지 목록과 provenance**
   - 피해야 할 시각 표현, 참고 자료 사용 범위, 생성 모델·프롬프트 기록 규칙을 정한다.
9. **실제 카메라 감사**
   - 대표 자산 하나를 `10`으로 제작해 엔진에서 검증한 뒤 전체 생산을 승인한다.

## 외부 연동

다양한 아트 방향 후보가 필요하면 `idea-diversity-engine`의 `visual-3d-design` 확장팩을 사용한다. 후보 생성은 방향 확정이 아니며, 본 스킬의 가독성·예산·일관성 게이트를 통과해야 한다.

## 하드 게이트

- 생성 이미지 한 장의 매력을 전체 아트 방향으로 일반화하지 않는다.
- 참고 작품의 고유 캐릭터, 로고, 구도, 스타일을 그대로 복제하지 않는다.
- 배경과 상호작용 물체가 실제 카메라에서 구분되지 않으면 승인하지 않는다.
- UI와 월드 아트가 동일한 강조 색을 경쟁적으로 사용하지 않게 한다.
- 예산이 없는 “고퀄리티” 지시는 자산 생산 계약이 아니다.

## 완료 게이트

- 실제 게임 카메라와 화면 크기가 고정됐다.
- 정보 역할별 실루엣·색상·움직임 규칙이 있다.
- 2D/3D/VFX/UI 자산별 기술 예산이 있다.
- 금지 스타일과 출처 기록 규칙이 있다.
- 대표 자산의 엔진 검증 계획이 있다.
